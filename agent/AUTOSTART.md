# Автозапуск локального агента TriDi

Агент должен подниматься сам после перезагрузки компьютера: если мастер включил
машину утром и ушёл в цех, ферма не должна стоять без заданий до тех пор, пока
кто-то не вспомнит про чёрное окно консоли. Агент при ошибках не выходит из
процесса (см. `agent/main.py` и SECURITY.md), поэтому автозапуск нужен только
на случай перезагрузки и обновления exe.

Ниже четыре способа: два для Windows, systemd для Linux и Docker, если нужна
изоляция. Достаточно одного.

Перед настройкой убедитесь, что агент запускается вручную: `TriDiAgent.exe`
рядом с `.env`, в котором вписаны `CRM_URL` и `AGENT_TOKEN` (файл создаётся при
первом запуске из зашитого `.env.example`).

## Windows: Планировщик задач (рекомендуется)

Планировщик умеет перезапускать упавший процесс и стартовать до входа в
систему — оба «Автозагрузка» не умеет.

1. `Win+R` → `taskschd.msc` → Enter.
2. Справа «Создать задачу…» (именно задача, а не «Создать простую задачу»: у
   простой нет настроек перезапуска).
3. Вкладка **«Общие»**:
   - Имя: `TriDi Agent`;
   - «Выполнять только при регистрации пользователя» — оставить, если нужен
     видимый журнал; «Выполнять вне зависимости от регистрации пользователя» —
     если окно консоли мешает (Windows спросит пароль учётной записи);
   - галочку «Выполнять с наивысшими правами» ставить **не нужно**: агент
     работает от обычного пользователя и прав администратора не требует.
4. Вкладка **«Триггеры»** → «Создать» → «Начать задачу»: **«При входе в
   систему»**. Для компьютера, который работает круглосуточно, добавьте второй
   триггер «При запуске».
5. Вкладка **«Действия»** → «Создать» → «Запустить программу»:
   - Программа: полный путь к exe, например
     `C:\TriDi\TriDiAgent.exe`;
   - Рабочая папка (важно): папка с exe, например `C:\TriDi` — рядом с ней
     агент ищет `.env` и создаёт `temp/`.
6. Вкладка **«Параметры»**:
   - ✅ «Перезапускать при сбое каждые: **5 минут**», «Количество попыток: 999»;
   - «Если задача уже выполняется» → «Не запускать новый экземпляр» (два агента
     на одном принтере устроили бы гонку заданий);
   - ❌ «Останавливать задачу, если она выполняется дольше…» — агент работает
     постоянно, этот предел его бы убивал.
7. Вкладка **«Условия»**: на ноутбуке снимите «Запускать только при питании от
   сети» — иначе после перехода на батарею задача не поднимется.
8. «ОК». Проверка без перезагрузки: правый клик по задаче → «Выполнить», затем
   `Get-ScheduledTaskInfo -TaskName "TriDi Agent"` — в `LastTaskResult` должен
   быть `0`. Ещё через полминуты в интерфейсе фермы принтеры станут «Свободен»,
   а не «Офлайн».

Обновить агент: остановить задачу («Завершить»), заменить exe и `.env` при
необходимости, снова «Выполнить». Настройки задачи при этом не меняются.

## Windows: папка «Автозагрузка»

Самый простой способ, но без перезапуска при сбое и только после входа в
систему:

1. `Win+R` → `shell:startup` → Enter. Откроется папка
   `C:\Users\<имя>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup`.
2. Правый клик по `TriDiAgent.exe` → «Отправить» → «Рабочий стол (создать
   ярлык)», затем перенесите ярлык в открытую папку (или сразу
   «Создать ярлык» в этой папке).
3. В свойствах ярлыка проверьте «Рабочая папка» — папка с exe и `.env`.
4. Перезагрузка: агент откроется окном консоли после входа в систему.

Минус честно: если процесс когда-нибудь завершится (например, его закроют
руками), сам он не вернётся — для фермы это Планировщик задач.

## Linux: systemd

Готовый unit-файл лежит рядом с этим документом —
`agent/tridi-agent.service`. Порядок установки (из корня репозитория):

```bash
# 1. Отдельный системный пользователь: агенту не нужен root.
sudo useradd --system --home /opt/tridi-agent --shell /usr/sbin/nologin tridi

# 2. Код и зависимости в /opt/tridi-agent.
sudo mkdir -p /opt/tridi-agent
sudo cp -r agent/. /opt/tridi-agent/
sudo chown -R tridi:tridi /opt/tridi-agent
sudo -u tridi python3 -m venv /opt/tridi-agent/.venv
sudo -u tridi /opt/tridi-agent/.venv/bin/pip install -r /opt/tridi-agent/requirements.txt

# 3. Настройки: тот же .env, что заполняли для ручного запуска.
sudo install -m 600 -o tridi -g tridi agent/.env /opt/tridi-agent/.env

# 4. Служба.
sudo cp /opt/tridi-agent/tridi-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tridi-agent
```

Проверка и обновление:

```bash
systemctl status tridi-agent          # active (running)
journalctl -u tridi-agent -f          # журнал агента, как в консоли Windows
sudo systemctl restart tridi-agent    # после замены кода
sudo systemctl disable --now tridi-agent  # выключить автозапуск и остановить
```

Что важно в unit-файле: `Restart=always` и `RestartSec=10` — systemd поднимает
агента через 10 секунд после любого завершения, включая падение при старте;
`User=tridi` — без root; `After=network-online.target` — не стартовать раньше
сети, иначе первый же опрос уйдёт в пустоту (агент это переживёт, но журнал
будет красным).

## Docker (опционально)

Если нужна изоляция от системы: агент в контейнере, на хосте — только Docker.
`Dockerfile` кладётся в папку `agent/`:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py scanner.py gcode_metadata.py ./
COPY adapters ./adapters
CMD ["python", "main.py"]
```

Сборка и запуск:

```bash
docker build -t tridi-agent agent/
docker run -d --name tridi-agent --restart=always \
  --network host \
  -v /opt/tridi-agent/.env:/app/.env:ro \
  tridi-agent
```

Честные ограничения контейнера:

- `--network host` обязателен: в bridge-сети агент не увидит принтеры и не
  сможет отправить UDP-бродкаст при поиске. Host-сеть в Linux работает как
  надо; в Docker Desktop на Windows и macOS она ограничена — для фермы берите
  обычный exe, а не контейнер.
- `.env` монтируется внутрь как файл: токен остаётся на хосте, а не в образе.
  Каталог `temp/` живёт внутри контейнера — это нормально, файлы удаляются
  после печати.
- `--restart=always` — тот же автозапуск, что Планировщик задач в Windows.
- Журнал: `docker logs -f tridi-agent`.

## Что выбрать

| Ситуация | Способ |
|---|---|
| Windows у принтеров, нужен автозапуск и перезапуск при сбое | Планировщик задач |
| Windows, нужно быстро и без настроек | папка «Автозагрузка» |
| Linux (Raspberry Pi у фермы, сервер в цеху) | systemd |
| Нужна изоляция процесса, Linux-хост | Docker |

Во всех случаях после настройки проверьте результат в интерфейсе: вкладка
«Принтеры» через полминуты показывает «Свободен»/«Печатает», а не «Офлайн» —
значит агент жив и пульс доходит до CRM.
